# Discovery findings

Phase 1 output: an inventory of the Webull OpenAPI as it exists publicly, taken
before any client code was written so that package boundaries, wire-format
choices and milestone scope are decided against the real API rather than an
assumed one.

Scope is the **US** market only. Webull operates twelve regional deployments
that share this API shape; the others are out of scope for now and are noted in
[environments.md](environments.md) so adding one later is a configuration change
rather than a redesign.

## Sources

1. Official documentation at `developer.webull.com/apis/docs` — 292 pages, of
   which 247 are endpoint reference pages.
2. `webull-inc/webull-openapi-python-sdk` — the current-generation Python SDK.
3. `webull-inc/openapi-python-sdk` — the previous-generation Python SDK.
4. `webull-inc/webull-openapi-java-sdk` and `webull-inc/openapi-java-sdk`.
5. `webull-inc/webull-openapi-cli` — a first-party CLI written in Go, useful as
   a cross-check on how Webull expects the signing algorithm to be expressed in
   Go.

All five repositories are Apache-2.0 licensed. They were read to understand
protocol behaviour; no source was copied. See
[open-questions.md](open-questions.md) for the licensing note.

## Reproducing this

Nothing here is generated by a committed script, because the inputs are third-party
repositories and a documentation site that we do not control and should not
vendor. To refresh:

```
git clone --depth 1 https://github.com/webull-inc/webull-openapi-python-sdk
git clone --depth 1 https://github.com/webull-inc/webull-openapi-java-sdk
git clone --depth 1 https://github.com/webull-inc/webull-openapi-cli
curl -s https://developer.webull.com/apis/sitemap.xml
```

Endpoint paths in the SDKs are plain string literals passed to the request base
class, so `grep -rhoE "['\"]/[a-zA-Z][a-zA-Z0-9/_-]{3,}['\"]"` over the package
directory recovers the full list.
